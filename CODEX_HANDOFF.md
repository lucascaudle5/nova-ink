## Implementation map
- main.ts: MCP endpoint at 127.0.0.1:3001/mcp, /health, and optional stdio.
- server.ts: UI resource, visible open_nova_ink launcher, and eight app-only notebook/recovery tools. Only the launcher declares the widget resource.
- http.ts: Express app (16 MB JSON limit, structured 413/400 errors, /health).
- storage.mjs: single-process JSON store, snapshots, ten valid prior backups, manifest backup/rebuild, optimistic revision checks, idempotent saveId, and 45-second editor lease (15-second UI heartbeat). Default data is %LOCALAPPDATA%\NOVA-Ink\data.
- backup.mjs + scripts/backup-data.mjs, scripts/restore-data.mjs: independent verified backup; restore only into an empty folder.
- src/session.ts: CanvasSession — all save/open/switch/conflict/recovery logic, testable without a browser. src/snapshot.ts: tldraw load validation.
- src/main.tsx: React/tldraw view over CanvasSession, status banners, backup panel, viewport-clipped Ask NOVA, top toolbar.
- src/context.ts: geometry and context selection. src/styles.css: notebook and backup panel.
- scripts/build-host-test.mjs: development-mode evaluation build.
- engine/ (branch engine/spike only): NOVA-owned engine spike, self-contained package with its own tests and browser harness; imports nothing from the app, tldraw, MCP, storage or cloudflare/. See engine/README.md and engine/docs/ENGINE_ARCHITECTURE.md.

## Accepted product decisions
1. Native ChatGPT on iPad, Apple Pencil first. Desktop is mainly for imports, organization, and development.
2. Independently named course canvases; resume the last canvas on launch.
3. Online-first server snapshots, honest Saved/Saving/Not synced status, and camera recovery. Durable offline support is deferred.
4. One active editor per canvas, with safe control handoff.
5. Preferred future Study Mode is native ChatGPT and canvas side-by-side. iPad v1 uses fullscreen canvas with a native conversation overlay; do not force unsupported metadata.
6. Put the drawing toolbar on top and preserve tldraw's native pen/touch feel.
7. PDFs should become separate movable pages with source provenance; page annotations travel with pages. Provide lock and detach controls.
8. Inspect selected items or the visible viewport first. Do not pan the user's camera.
9. No unsolicited hints. Student initiates chat hints and any Annotate Canvas action. Do not show arbitrary percent-correct estimates.
10. Distinguish independent work, hints, and AI-authored annotations in future learning records.
11. Long-term replay/event ledger is required but not implemented.

- Backups are on the host machine; no tested off-machine recovery.
- Single-process JSON prototype with 12 MiB per-canvas limit; separate server processes do not coordinate leases.
- AI annotation mode is not implemented.
- Top toolbar and backup UI have not been verified on iPad (they await a user test batch).
- No guaranteed iPad side-by-side interaction.
- Tldraw licensing is required before production.
- Secrets, private tunnel identity, and actual notebook data stay outside Git.

### NOVA prepares, draws on and arranges the study canvas (October 30, 2026; built and tested locally, committed on engine/spike; deployed to nova-ink-engine on October 30, 2026 at 2:2x PM, Worker version b8702357-ee70-4b09-80d3-d3d12251d982, on the user's explicit instruction; the root URL answered 200; no real-ChatGPT or iPad check yet)

**What exists.** NOVA can, through conversation: (1) put PDF pages or rectangular problem crops into a notebook, each on its own page with free room beside/below or stacked with working space; (2) draw attributed, editable diagrams (lines, arrows, rectangles, ellipses, arcs, polylines, text, equations) beside the student's work; (3) move, align, distribute, group, ungroup, duplicate and (NOVA-only) remove objects, make room, and copy a picture to a fresh page. **Tools (all added to the engine Worker's MCP; none changes existing tools).** `nova_list_notebooks` (also lists stored sources), `nova_notebook` (page structure), `nova_read_page` (text scene: page size, objects with ids, bounds, groups, clusters of the student's ink as `ink:<firstStrokeId>` regions; handwriting is NOT read and there are no image previews yet), `nova_edit_page` (operation list, grammar in the tool description; `requestId` makes retries idempotent; optional `expectedRevision` returns STALE_REVISION), `nova_op_status`, `nova_place_source`, `nova_organize`, `nova_import_file`. Scopes: read tools need mcp:read, writes need mcp:write.

**Where the work happens.** The planner/shapes/typesetter live in `engine/src/core` (`ops.ts`, `shapes.ts`, `typeset.ts`, `font.ts`, `scene.ts`), independent of ChatGPT, Drive and hosting. Drawings are stroke polylines (author `ai`, group `nova-<name>-<8hex>`, purple, with a boxed "N" badge so they are distinguishable without colour), so selection, moving, saving, reopening, undo and redo are the engine's own. The Worker's PageDO queues a request (deterministic ids from a server-generated opId; dry-run planned on top of already queued requests; at most 30 waiting). If a notebook is open (live lease) the widget pulls waiting requests on its heartbeat (about 6 s) and applies each as ONE undo step through the same planner; the Worker never overwrites an open editor's snapshot. If no editor is live the Worker applies and saves the request itself (no lease needed; the next open shows it). Status: queued -> applied (shown in the open notebook) -> saved (durable on the server; settled in the save transaction). Failed or no-change requests are reported once with a reason. Writing with the Pencil while a request is waiting delays application until the pen is up; a student's stroke is never replaced. Placement nudges away from existing ink; retries (same requestId, or redelivery) never duplicate.

**PDF sources.** The Worker cannot render PDFs, so pdf.js in the open notebook does it. Inserting a PDF from the notebook (file picker, including the Files app and Google Drive in the iPad picker) now also stores the original as a source (id `src_<sha-256 prefix>`, 24 MB cap) and records document name, page number and crop on each picture (`nb_set_image_meta`). `nova_place_source` queues a render job; the open notebook renders the pages or crops (a crop keeps the page's scale) and the server places them. Jobs wait while the notebook is closed. `nova_import_file` accepts a ChatGPT file parameter (https download URL, 24 MB, must start with %PDF-) but that route has NOT been tried in real ChatGPT; a Drive link is not assumed downloadable by the Worker.
